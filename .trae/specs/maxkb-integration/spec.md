# 全场景AI日志分析平台 - 知识库与RAG核心功能重构集成 Spec

## Why
目前基于若依（Vue3 + Spring Boot 4）的全场景AI日志分析平台已经初步实现了简单的模型管理与智能体管理。为了进一步提升平台在复杂运维场景下的日志分析深度与准确性，需要引入RAG（检索增强生成）能力，以便将历史故障日志、运维手册（Runbook）和系统架构文档等外部知识注入到大模型中。通过参考开源项目 `MaxKB4j`，重构并实现若依框架原生不具备的知识库管理、文档解析切分、向量化检索等核心功能，快速补齐平台能力短板。

## What Changes
- **新增** 知识库管理模块（重构自MaxKB4j），支持上传各类运维文档、日志集，并进行配置与维护。
- **新增** 数据处理流水线（包含文档解析、自定义分段策略、数据清洗）。
- **新增** 向量化与存储能力，对接主流向量数据库（如Milvus、Qdrant或PgVector），实现文本Embedding存储与检索。
- **新增** 命中测试模块，用于独立校验日志片段或运维查询的检索准确率。
- **修改** 现有的智能体管理模块，支持将特定领域的知识库关联至智能体，并配置检索参数（如相似度阈值、引用Top-K）。
- **修改** 聊天/分析对话接口，整合检索（Retrieval）与大模型生成（Generation）逻辑，实现基于本地知识库的问答能力。

## Impact
- Affected specs: 智能体配置能力、大模型对话生成能力、日志智能分析流。
- Affected code: `ruoyi-ui`前端模块（新增知识库相关视图及组件）、`ruoyi-admin`或新建的AI业务模块（引入向量库SDK、LangChain4j或相关RAG组件、数据表模型）。

## ADDED Requirements
### Requirement: 知识库管理与文档解析
系统必须提供知识库的创建、更新与删除功能，并支持常见格式（TXT, PDF, Word, Markdown等）以及日志文件的上传、解析和自定义文本分段（Chunking）。

#### Scenario: 成功创建并解析知识库文档
- **WHEN** 运维人员上传一份《系统错误码排查手册》或历史错误日志集，并选择相应的分段策略与Embedding模型。
- **THEN** 系统将其解析、切分，转化为向量数据存入向量数据库中，并将文档状态变更为“解析完成”。

### Requirement: 命中测试与检索调优
系统必须允许管理员或运维人员针对特定知识库进行检索测试，以验证文本切片策略的有效性。

#### Scenario: 命中测试校验检索准确率
- **WHEN** 用户在命中测试界面输入一段真实的报错日志片段（如 `java.lang.OutOfMemoryError`）。
- **THEN** 系统展示从知识库中检索出的最相关Top-K文档分段及其相似度得分。

### Requirement: 智能体关联知识库（RAG检索）
系统必须允许用户在配置AI智能体时，选择一个或多个知识库作为上下文来源，并设定相关的检索策略。

#### Scenario: 成功的日志分析问答
- **WHEN** 用户在分析平台向关联了《应用运维知识库》的智能体发送一段报错日志。
- **THEN** 系统先从知识库中检索相关的排查步骤或历史解决方案，将上下文与用户日志组合后发送给大模型，最终返回带有引用来源的日志分析报告。

## MODIFIED Requirements
### Requirement: 智能体管理模型与界面
在原有智能体管理界面和数据表结构中，增加关联知识库的字段与配置项（检索相似度阈值、引用文档数量上限等），使得智能体可以根据具体场景调用不同的日志经验库。

## REMOVED Requirements
无。
